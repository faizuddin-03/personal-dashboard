# Flows

One flow per module: a function that drives a whole journey through the page
objects, with `stopAfter` naming the step just completed, defaults for every
option, and a result that carries what the next step needs. A CR's spec calls
flows and adds its own assertions. **Journey code never lives inside a spec.**

Status meanings:

- **VERIFIED**: run live end to end, evidence reviewed, date and run recorded here.
- **LEGACY**: existed before this rule and has been used in live runs. Trusted,
  but if it misbehaves, re-verify it.
- **UNVERIFIED**: built, not yet proven. **A CR spec must not use it.**

## The rule: a new flow is not official until it has run live

A flow being written, or typechecking, proves nothing about the selectors. Until
it has been run against the environment it drives, its status is UNVERIFIED and
no CR spec may call it.

To move a flow to VERIFIED:

1. **Verify spec.** `automation/tests/flows/<flow>.verify.spec.ts` calls the flow
   with every `stopAfter` that matters, and asserts on the screen each stop
   claims to be sitting on (not just "did not throw"). Tag it `@destructive`
   when the flow changes records.
2. **Run it live** on the environment the flow targets (staging by default),
   through `cr-runner` or by hand. Run it more than once when the flow allocates
   data, so a first-run fluke does not pass.
3. **Review the evidence** (screenshots and video) per the evidence-review rule:
   right screen, right transaction, the claimed state visible.
4. **Flip the row** to VERIFIED with the date, instance and run reference.
   `cr-evidence` does this (Azfar, 09.10.2026) when every stop of the verify
   run is `ok` on the right instance — never the agent that wrote the flow,
   and never from the run result alone. The QA can flip it back.

A change to a VERIFIED flow or its page objects sets it back to UNVERIFIED until
steps 2-4 are repeated.

## Building a flow (module has none, or the CR needs a stop it lacks)

1. Probe the live screens read-only for selectors; never write one unseen.
2. Page-object methods first, in `src/pages/<slice>/`, one object per screen.
3. Then the flow, shaped like `stms.flow.ts`.
4. Add it to the registry as UNVERIFIED, write the verify spec, then follow the
   steps above before any CR uses it.
