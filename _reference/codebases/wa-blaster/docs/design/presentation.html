03 · FOUNDATIONS

App shell — three viewports

Fixed left sidebar (240 px expanded, 64 px collapsed icon-rail), 56 px top bar with breadcrumbs · search · quality pill · theme toggle · help · role pill. Tested at 1440 / 1024 / 375 px.

1440 — desktop
1024 — tablet
375 — phone
1 2 3
1Desktop · 1440 px. Full sidebar with section labels (Workspace / Admin / Help) and badge counts. Active route gets a 3 px green-500 left accent bar and green-100 background.
2Tablet · 1024 px. Sidebar auto-collapses to an icon rail at <1100 px regardless of the stored preference. Breadcrumbs hide; search input shrinks.
3Phone · 375 px. Stat strip reflows to one column; KPI strip stacks. User-menu name hides, leaving the avatar. Tables horizontally scroll (sticky first column).

Workflow storyboards

Three daily workflows mapped as horizontal node-and-arrow strips. Stakeholders can validate flows before any code. Every step is clickable — it deep-links into the matching screen.

/?r=workflows
Workflow B branches. The "create → schedule → monitor" flow has an alternate terminus — Detail · failed with Meta error log + retry — branching off after the launch dialog. This is rendered as an explicit "or" branch on the diagram so the failure path is visible at a glance.

10

Notification design

Toast variants (success / info / warning / destructive) plus the undo pattern with 5-second countdown. In-app badge sits in the sidebar nav and on the inbox-tab counts.

components.html#toast
Destructive actions get an undo, not a confirmation modal. When you delete contacts, the rows disappear immediately and a toast appears with Undo (5s). The progress bar at the bottom of the toast counts down. Bulk send / launch is the only destructive action that still uses an AlertDialog — because it is genuinely irreversible (real messages hit real phones). § 9
NOTE

Deviations from the spec

Two minor calls; flagged here for review.

aSidebar order. Spec § 4.2 lists Inbox first. The prototype defaults the landing route to the Workflows page (§ 7) so reviewers see the three flows at a glance; production should default to Inbox. Trade-off: discoverability of flow diagrams vs. operational landing.
bTop-bar quality pill. Spec doesn't mandate this surface; added at request of § 4.3-adjacent operational concerns. It's a high-signal status that operators check several times a day. Trade-off: a bit more chrome in the topbar (still calm).
Live previews stay in sync with the prototype. Print this page (⌘P) for a static PDF version.
