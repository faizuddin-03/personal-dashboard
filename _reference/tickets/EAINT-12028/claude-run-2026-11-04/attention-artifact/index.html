F11 · TS54

The PDF address ignores the month (in plain terms)

low risk

Every month's PDF has its own web address, for example …/association/2026/5/7f66cb31-…/pdf?type=FMC. It has two parts: the month number ("5" = May) and a long code that is the month's real ID.

Think of a parcel locker. The long code is the locker key, and the month number is just a name written on the slip. I changed the slip from "5" (May) to "1" (January) but kept May's key. The server ignored the slip, opened the locker with the key, and handed over May's PDF.

Harm
None found. It only ever gave May's PDF, which was already approved and downloadable. Trying January's own key was refused, so no unapproved month leaked.
Why log it
The TS expects an edited address to be refused. A tidy server would check that the slip matches the key, and refuse if they don't.

Related, from TS69: a forced Reject on fully approved May was refused correctly, but the message says "cannot act until the Reviewer has approved", and May's Reviewer has already approved.

Your call: raise as Low, or accept.
