Ticket: EAINT-12175 — [Secarang & eAuto-Insurance] To Correct Insurer Name to

Context: Lonpac's display name is being standardised from "Lonpac Insurance
Berhad" to "Lonpac Insurance Bhd". Secarang's 5 pages (REQ-001 to REQ-005)
are already deployed to production. The remaining work is on eAuto: 4
requirements (REQ-012 to REQ-015) added in SRD v1.1 to fix a SHARED
plan-code label used by an Insurance Company filter dropdown and its
result table, on both the UCD portal and the BackOffice portal.

1. Requirement list to trace in code:
   a. REQ-012 — BackOffice Insurance Enquiry search screen, Insurance
      Company filter dropdown. Label must read "Lonpac Insurance Bhd".
   b. REQ-013 — BackOffice Insurance Enquiry, result table, Insurance
      Company column. Must read "Lonpac Insurance Bhd" for Lonpac rows.

      Insurance Company filter dropdown. Same label fix.
   d. REQ-015 — UCD result table, Insurance Company column, on the same
      two screens. Must read "Lonpac Insurance Bhd" for Lonpac rows.

2. Find the shared label / lookup mechanism.
   a. The SRD calls it a "shared plan-code label" — find the single source
      (constant, enum, lookup table, or database seed row) that maps the
      insurer's plan code to its display name "Lonpac Insurance Berhad" /
      "Lonpac Insurance Bhd".
   b. List every screen, filter, dropdown, table column, report, or export
      that reads from that same source. The SRD itself flags this risk on
      REQ-012: "Any other screen using this shared label also displays
      'Lonpac Insurance Bhd'" — confirm whether that is true, and name
      every such screen, not only the 4 requirements above.

3. Check the specific pages already confirmed correct (no code change
   expected, verify nothing else on these pages reads the same shared
   label used in item 2):
   a. UCD Insurance Quote & Optional Coverage
   b. UCD Policy Detail view
   c. BackOffice Policy Detail view
   d. eSTM Transaction Detail view
   e. Credit Portal (hire-purchase/service portal) Insurance Enquiry
   f. Backend-generated Receipt PDF

4. Check one item the ticket leaves unresolved: the original ticket
   description named an "Insurance Dashboard" chart series label as also
   using the shared plan-code label, but SRD v1.1's REQ-012 to REQ-015 do
   not mention a chart. Find the Insurance Dashboard (menu location,
   route, or component) and confirm whether its chart reads from the same
   shared label. Report whether it needs the same fix or was correctly
   dropped from scope.

5. Explicitly out of scope — do not flag these as needing the fix, but do
   confirm they are NOT touched by whatever code change satisfies items 1
   and 2 (a regression risk, not a new requirement):
   a. Secarang PDS (Product Disclosure Sheet) link — stays on the old
      pds-sdpa.pdf naming pattern by design.
   b. Secarang PDF receipt (backend-generated) — separate service, out of
      scope by design.
   c. CIBO Admin Portal and Serba Sentral API — flagged inconsistent in
      the impact assessment but explicitly not part of this request.
   d. The "(307414-T)" company registration number format — unrelated,
      separate compliance matter.
   e. Other insurers' naming (Tokio Marine, RHB, Chubb, Takaful) — must
      stay untouched.

6. Output wanted: a list of every file/page/component that (a) must
   change to satisfy REQ-012 to REQ-015, (b) reads the same shared label
   but isn't named in the SRD (the hidden-blast-radius check), and (c)

   constant, or query that ties it to the shared label.
