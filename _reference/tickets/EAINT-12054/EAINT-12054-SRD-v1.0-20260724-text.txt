2.0  REQUIREMENT
2.1  High-Level Requirement Overview
#
 | Item
 | Description
 |
---
2.1.1
 | Enhancement Overview
 | Introduce SSM validation checking during the STMS bulk payment process, based on the user's SSM bypass permission and the transaction's Seller Category (Company).
 |
---
2.1.2
 | Key Value(s) Expected
 | Prevent STMS bulk payments from proceeding when the required SSM documents have not been purchased, ensuring SSM compliance before payment.
 |
---
2.1.3
 | Additional Note(s)
 |  |
---
2.1.1  Assumptions
#
 | Assumption
 |
---
1
 | The existing SSM validation logic for STMS transactions remains in place and is reused within the bulk payment flow.
 |
---
2
 | “3 required documents” refers to the existing set of SSM documents already defined in the system.
 |
---
3
 | SSM bypass permission is an existing, configurable user-level permission.
 |
---
4
 | Seller Category “Company” is an existing attribute available on STMS transactions.
 |

2.2.2  Existing Issue & Expected Behaviour
#
 | Item
 | Description
 |
---
1
 | Existing Issue / Behaviour
 | Currently the system does not validate the user's SSM bypass permission during the STMS bulk payment process.
As a result, STMS payments can be processed even when the required SSM documents have not been purchased.
 |
---
2
 | Expected New Handling / Behaviour
 | Scenario 1 — UCD with SSM bypass purchase: on bulk payment submission, the system ensures the transaction has all 3 required documents uploaded before allowing the STMS payment to proceed.
Scenario 2 — UCD without SSM bypass purchase: on bulk payment submission, the system proceeds with transactions that fulfil the requirements.
If the SSM docs are no longer valid, the system shows the affected transaction numbers on a popup.
UCD must resubmit the transaction from the STMS transaction listing to purchase the SSM docs.
 |

2.2.4  Required Documents by Business Type
Under Company Details, the required documents differ based on the selected Type of Business and whether the user has purchased the SSM bypass. A user with SSM bypass purchase must upload all 3 documents; a user without SSM bypass purchase only needs to upload the Board Resolution / Authorisation Letter.

 | Without SSM Bypass Purchase (mandatory)

 | Authorisation Letter
 |

 | Limited Liability Partnership (LLP)

2.2.5  STMS Bulk Payment – SSM Validation
#
 | Requirement ID
 | Item
 | Description
 | Acceptance Criteria
 |
---
1
 | EAINT-12054-REQ-001
 | SSM Bypass Permission Check
 | The system validates the user's SSM bypass permission during the STMS bulk payment process, for STMS transactions where the Seller Category is Company.
 | On bulk payment submission, the system checks the user's SSM bypass permission before processing STMS transactions with Seller Category = Company.
 |
---
2
 | EAINT-12054-REQ-002
 | Validation — With Bypass Permission
 | If the user has SSM bypass permission, the transaction must have all 3 required documents uploaded (as listed in Section 2.2.4, based on the Type of Business) before the STMS payment can proceed.
 | A transaction under a user with bypass permission proceeds only when all 3 required documents for the applicable business type are uploaded; otherwise the payment is blocked.
Example 1: Sdn Bhd/Bhd
Payment proceeds only when SSM Company Profile, Company Board Resolution, and Staff Employment Pass & MyKad are all uploaded; otherwise the payment is blocked.
Example 2: Sole Proprietorship / Partnership
Payment proceeds only when SSM Business Profile, Authorisation Letter, and Staff Employment Pass & MyKad are all uploaded; otherwise the payment is blocked.
Example 3: LLP
Payment proceeds only when LLP Profile, Authorization Letter, and Staff Employment Pass & MyKad are all uploaded; otherwise the payment is blocked.
 |
---
3
 | EAINT-12054-REQ-003
 | Validation — Without Bypass Permission
 | If the user does not have SSM bypass permission, the system performs the following checks in sequence:
1. Check whether the Board Resolution / Authorisation Letter (the applicable document per business type in Section 2.2.4) is uploaded.
2. If uploaded, check whether the SSM documents are still valid.
3. If the SSM documents are still valid, the transaction proceeds; otherwise, the transaction is blocked.
If the Board Resolution / Authorisation Letter is not uploaded, the transaction is blocked.
 | For a transaction under a user without bypass permission: when the Board Resolution / Authorisation Letter is uploaded and the SSM documents are still valid, the payment proceeds; if the letter is missing or the SSM documents are no longer valid, the payment is blocked.
Example 1: Sdn Bhd / Bhd
Payment proceeds only when the Company Board Resolution is uploaded and the SSM documents are still valid; if the Company Board Resolution is missing or the SSM documents are no longer valid, the payment is blocked.
Example 2: Sole Proprietorship / Partnership
Payment proceeds only when the Authorisation Letter is uploaded and the SSM documents are still valid; if the Authorisation Letter is missing or the SSM documents are no longer valid, the payment is blocked.
Example 3: LLP
Payment proceeds only when the Authorization Letter is uploaded and the SSM documents are still valid; if the Authorization Letter is missing or the SSM documents are no longer valid, the payment is blocked.
 |
---
4
 | EAINT-12054-REQ-004
 | Proceed Qualifying Transactions
 | On bulk payment submission, the system proceeds with the transactions that fulfil the SSM requirements.
 | Transactions meeting all SSM requirements are processed within the bulk payment; non-qualifying transactions are not processed.
 |
---
5
 | EAINT-12054-REQ-005
 | Invalid SSM Docs Popup
 | If the SSM documents are no longer valid, the system displays the affected transaction numbers on a popup. UCD must resubmit those transactions from the STMS transaction listing to purchase the SSM docs.
Suggested error message:
“SSM documents for the following transaction(s) are no longer valid: [Transaction No]. Please resubmit the transaction(s) from the STMS Transaction Listing to purchase the SSM documents before proceeding with payment.”
 | When SSM docs are invalid, a popup lists the affected transaction numbers with the above message, and those transactions are not processed until resubmitted from the STMS transaction listing.
 |
